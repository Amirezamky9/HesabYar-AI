## Key plan decisions

- Tests run against SUPABASE: source
  `~/workspace/projects/hesabyar-reference/.env.supabase`
  (`HESABYAR_DATABASE_URL` + `HESABYAR_TRYTON__BASE_URL=http://localhost:8010`)
  before any pytest/FastAPI run. Trytond :8010 serves the Supabase Tryton
  DB; start it with `start-trytond-supabase.sh` (password from ~/.pgpass).
- SERIALIZE pytest: never run two pytest processes concurrently — they
  deadlock on the shared HesabYar test DB. CRITICAL: the Phase 4 phase-end
  full suite is STILL RUNNING when this plan is written — NO DB-touching
  pytest until the parent confirms it finished. Start with worktree setup,
  scaffolding, DB-free tests, frontend work, and Tryton console/module
  work (Tryton DB, not the HesabYar test DB).
- Per-story verification is TARGETED tests only (story tests + affected
  areas + ruff + pyright); full suite once at wave-end (user's policy
  since 2026-11-17).
- Architecture guard: the 16-test Phase 4 guard (no port bypass, no direct
  SQL to the Tryton DB) must stay green. Application services depend only
  on ports; SQLAlchemy lives in infrastructure/persistence/postgres/.
- No hard-coded rates, no hard-coded channel lists (grep-verified).
  Fee % is user-entered per channel/contract; rate change = new versioned
  contract with an effective date. Ilmaz is NOT a built-in channel.
- No browser automation / RPA / screen-scraping as a product path (ADR
  0003 update 4). No internet-banking passwords stored, ever.
- Fintech inquiry results are ephemeral: store verdict/code/time only.
- Persian-only, Rial-only product (standing). VibeFarsi/FarsiUI via the
  existing facade for US-504. BFF auth pattern for new dashboard pages.
  No fake data anywhere.
- US-502 spikes (§3.8) close BEFORE building on them; path 1 (wizard) vs
  path 2 (direct journal via port) chosen + documented after the spikes.
- Inventory accounting method (continental vs anglo-saxon) decided before
  installing account_stock_*.
