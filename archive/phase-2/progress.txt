## Deferred (consolidated by US-205, 2026-11-17 — every item from US-201..US-205 with its reason; nothing silently dropped)
- US-201: reversal is NOT atomic (create the reversal draft, then post it — 2 REST calls, not one transaction). Reason: REST has no wizard endpoint and `Move.cancel` is not in `__rpc__`, so the adapter replicates the cancel wizard with two calls. A failed post surfaces `reversal_draft_id` for recovery; the service retries the post once.
- US-201: reversal does NOT reconcile reconcile-account lines. Reason: `account.move.line.reconcile` is not RPC-exposed, so no REST path exists to replicate that part of the wizard.
- US-201: closed-account / closed-period post rejections are unit-tested only (mocked transport). Reason: the engine makes those states unreachable via REST (it refuses to create lines on closed accounts / moves in closed periods), verified live — the adapter still checks them at post time as defense-in-depth.
- US-202: journal-draft LIST (`GET /accounting/journal-drafts`) and UPDATE (`PATCH /accounting/journal-drafts/{id}`) were 501 `NOT_IMPLEMENTED` stubs. Reason: the engine port had no list/update operation (US-201 scoped it to create/validate/post/reverse) and US-204 owned port/adapter changes in this wave, so US-202 could not add one. CLOSED 2026-11-17 by the follow-up (commit c506aaf: port methods `list_journal_drafts` + `update_journal_draft`, adapter REST implementations, wired service/router, no 501s remain for journals) — coordinator-verified, US-202 marked passed (7bec2fa).
- US-202: `get_journal_draft` was declared on an application-layer protocol (`JournalEngine`) instead of the port, because the adapter provided it publicly but US-201 did not declare it on the port. CLOSED 2026-11-17 by the follow-up (commit c506aaf): `get_journal_draft` joined the port and the protocol collapsed back to `AccountingEnginePort` — coordinator-verified with the item above, US-202 marked passed (7bec2fa).
- US-202: idempotency crash window — if the process dies between the engine confirming a post and the response being stored, a retry surfaces 409 `LEDGER_POSTED_IMMUTABLE` instead of the replay (never a silent duplicate). Fixing it needs a post-confirmation read-back keyed to the idempotency record.
- US-202: no housekeeping purges expired `idempotency_records` (24h TTL) or stale pending claims (10m TTL); a purge job is a later story.

Reason: the follow-up wired the operation but not the idempotency/audit plumbing. Needs: claim-before-execute + audit event on PATCH, like create/post/reverse.
