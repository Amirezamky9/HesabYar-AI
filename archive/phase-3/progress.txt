# HesabYar Phase 3 — progress log

Branch: `ralph/phase-3`. Plan: 5 stories (US-301 shell+auth+facade → US-302 dashboard+accounts → US-303 journals → US-304 invoices/payments/statements → US-305 reports+export+responsive/a11y+e2e). Waves: A: US-301 alone; B: US-302/US-303/US-304 parallel; C: US-305.

## Decisions (from the plan)

- Auth: operator logs in with an API key via a Next.js BFF route; BFF validates against FastAPI, issues an httpOnly session cookie, keeps the key server-side; browser never holds the key after login; all data calls through BFF routes (spec §19 rule 1, §4 line 252).
- Components: VibeFarsi (vibefarsi.ir, via CLI) for Persian-specific patterns + FarsiUI (farsiui.ir) for accessible primitives, per spec §5.2 and the user's explicit direction; unified facade at components/ui (§5.3); never two implementations of the same primitive on one page; MIT attribution preserved.
- Reports honesty: no backend report endpoint exists (get_report deferred in Phase 2; accounts carry no balances). Phase 3 reports only what the live API supports; trial balance / P&L / balance sheet / cash flow stay coming-soon — never faked, never computed client-side from paginated lists.
- pnpm is NOT installed in the VM (Node v24.22.1, npm 10.9.4); US-301 installs it (corepack enable, fallback npm i -g pnpm).
