## COORDINATOR FIX — pydantic date-field clash (b9fec67, 2026-11-20 ~23:55)
- Caught while counting OpenAPI paths on the merged head: importing the
  app raised PydanticUserError (unevaluable-type-annotation) —
  GeneralLedgerLineResponse, ForecastItemResponse and CalendarDayResponse
  all declared 'date: date'. With 'from __future__ import annotations'
  pydantic resolves the annotation against the class namespace, where
  'date' is the field itself. This broke the WHOLE app import (every
  REST test + the server would fail at collection/startup) and was
  invisible to ruff/pyright/tsc/eslint/build — static gates do not
  evaluate pydantic models. Fixed with the 'date as _date' alias
  (precedent: domain/bank/parsing.py); field name + JSON shape unchanged.
  NOTE: the 'datetime.date' qualification used in journals.py etc. does
  NOT work here — this module imports datetime the class, so
  datetime.date is the .date() method (proven by the second error).
  After the fix the app imports cleanly and OpenAPI reports 252 paths.
